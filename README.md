# ゆかちーダッシュボード

**第35回 NEC軽井沢72ゴルフトーナメント**（2026年8月14日〜16日／軽井沢72ゴルフ 北コース）で、
NEC所属のホステスプロ **安田祐香** が初日に大会コースレコードタイの「61」をマークし、
第2ラウンドの「64」と合わせて **36ホール125ストローク＝JLPGAツアー新記録**（2003年 アニカ・ソレンスタムの126を
23年ぶりに更新）を樹立、通算19アンダー・7打差の単独首位で最終日を迎えるまでを追う1枚もののダッシュボードです。

## 中身

| セクション | 内容 |
|---|---|
| ヒーロー | 大会通算スコア、順位、2位との差の推移、54ホール進行メーター、記録置換帯 |
| 54ホールの推移 | 大会全体を1本の線で。ラウンドの区切り、未消化区間の網掛け、リード差リボン、マイルストーン |
| ラウンド別リプレイ | 通算／各ラウンドを切り替えて1ホールずつ再生。グラフ・ホール帯・実況ログ・タイルが同期 |
| リーダーボード | 最新時点の順位表、カットライン、首位からの距離のラダー、残りホールの足し算 |
| 読み解き | シーズンスタッツと突き合わせたインサイト（各項目に時点バッジ） |
| 2026スタッツ | 平均ストローク・パーオン率・飛距離などのツアー内順位（大会中のスタッツではない） |
| 直近の成績 | 本大会の進行状況、北海道meijiカップ3位ほか |
| プロフィール / 道具 | 基本情報、アマチュア実績、2026年のクラブセッティング |
| 応援 / 出典 | 応援コメントと、参照した情報源へのリンク |

## ファイル構成

```
data/tournament.json   ← 唯一のデータソース
src/page.html          ← 唯一の編集元（HTML / CSS / JS）
scripts/build.mjs      ← データを注入し、以下2つを書き出す
index.html             ← 単体で開ける完全なHTML文書（生成物・直接編集しない）
dist/artifact.html     ← 公開用フラグメント（生成物・直接編集しない）
```

### 陳腐化しない仕組み

画面に出る数値は、すべて `derive()` が `rounds[].holes[]` から導出します。
`data/tournament.json` に直書きしてよいのは **外部の参照記録・出典・散文** だけです。
散文に数値を埋めたいときは `{strokes}` `{toPar}` `{margin}` `{holesLeft}` `{holesTotal}` などの
プレースホルダを使います（実際の値は導出結果から差し込まれます）。

そのため、**最終ラウンドのデータを `rounds[2]` に入れて `pending` を外すだけ**で、
通算スコア・順位・進行メーター・見出し・応援文・リプレイのタブ・期限切れのインサイトの除外まで、
`src/page.html` を1文字も変えずに追随します（検証済み）。

## 更新のしかた

1. `data/tournament.json` を編集する（第2ラウンドなら `round1` に相当するブロックを増やす／`meta.generatedAt` と `meta.roundStatus` を更新する）
2. ビルドする（`index.html` は生成物なので直接編集しないこと）

```bash
node scripts/build.mjs
```

3. `index.html` を再公開する

## ライブ更新について

このダッシュボードは**自動でスコアを取りに行きません**。理由は2つあります。

- 公開ページ側：配信環境のCSPが外部ホストへの通信（fetch / XHR / WebSocket）を一律ブロックするため、ブラウザからスコアAPIを叩けない
- 生成側：この開発環境のegressポリシーが、ゴルフ情報サイトおよびスコアAPIへの直接アクセスを遮断しているため、スクレイパーを常駐させられない

そのため、**データの更新はエージェントが検索経由で取得し直して `data/tournament.json` を書き換える運用**にしています。

この運用は**毎日21:00（JST）に自動で回る定期タスク（Routine）として登録済み**です。
1サイクルは「検索で最新情報を取得 → `data/tournament.json` を更新 → `node scripts/build.mjs` →
ブラウザで目視確認 → 同じURLへ再公開 → ブランチへコミット・プッシュ」。
新しい情報が見つからない日は、意味のないコミットを作らずに何もしません。

### スコアAPIを使いたい場合

`scripts/fetch-live.mjs` を取り込み口として置いてあります。

```bash
NODE_USE_ENV_PROXY=1 GOLF_API_KEY=xxxx \
  node scripts/fetch-live.mjs "https://api.sportradar.com/golf/trial/v3/en/lpga/2026/tournaments/schedule.json?api_key=\$GOLF_API_KEY"
```

レスポンスを `data/raw/` に生のまま保存し、トップレベルの構造を表示します。
**フィールドのマッピングは意図的に未実装**です。レスポンスの実物を一度も観測できていない状態で
マッピングを書くと、動いていないのに動いて見えるコードになるためです。実物が1件取れた時点で変換を書き起こします。

現在、以下のホストは egress ポリシーによって拒否されています（`403 to CONNECT`）。

```
api.sportradar.com
developer.sportradar.com
lpga-api.azurewebsites.net
```

使うには、環境のネットワークポリシーでこれらのホストを許可する必要があります
（参照：https://code.claude.com/docs/en/claude-code-on-the-web ）。
状態は `curl -sS "$HTTPS_PROXY/__agentproxy/status"` で確認できます。

なお、**許可されても目的のデータが取れるとは限りません**。Sportradar Golf API および LPGA の API が
カバーするのは主に米国LPGAツアーで、NEC軽井沢72は**JLPGA（日本女子プロゴルフ協会）ツアー**の大会です。
JLPGAが対象に含まれるかは、実際にスケジュールのエンドポイントを叩いて確認する必要があります。

## デザインの決めごと

- **アンダーパーは赤**。日本のゴルフ中継・リーダーボードの慣習に合わせています
- カラーパレットは配色検証スクリプトで、ライト／ダーク両モードの明度帯・彩度下限・色覚多様性下での分離・コントラストをすべてPASS済み
- Webフォントは使っていません（CSPでフォントCDNが遮断されること、和文書体はインライン埋め込みにはサイズが大きすぎることの両方による）
- ライト／ダークの両テーマに対応。トークンで定義しているので、片方だけ壊れることはありません

## 出典

数値・エピソードの出典はページ下部の「参照した情報源」に全件リンクしています。
日本語表記を確認できなかった選手名は、捏造を避けるため「ほか3名」のような人数表記にまとめてあります。
